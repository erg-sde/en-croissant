- [verified] kibitz (ekkx, Rust, GPL-3.0-or-later): architecture = Stockfish + deterministic code compute ALL facts; the LLM has 'exactly three degrees of freedom: which of the given facts matter, what order, what words'. Output order: (1) conclusion in classification terms, (2) how the opponent punishes it — walk counterfactual.pv naming counterfactual.motifs (or what collapses after the alternative), (3) positional reasons from static_diff.changes/outlook, 'two or three at most'; 120–200 words; address player as 'you'; moves exactly as SAN given.

## Implications
- BAR (what 'strictly better than chess.com Game Review commentary' requires), 1 — Every per-move explanation must state a concrete, machine-verified reason, never a bare label: the single most-repeated chess.com complaint is 'labels without reasons'. Minimum content for a ?/??: (a) the refutation line (engine PV from the position AFTER the played move, i.e. analysis[i].best[0] of the next position), (b) the tactical motif in that line expressed as piece+square facts (fork/pin/skewer/hanging/back-rank/mate-in-N), (c) the better move and the ONE idea behind it, (d) the eval/win-chance delta in words.
- BAR 2 — Zero fabricated board facts. chess.com's wrong-piece errors ('loses a knight' vs bishop) and ThinkFish/dev.to hallucinations are the same failure class. Architecture must make it impossible: the LLM receives only a closed fact set (kibitz's 'if it is not in the JSON, it does not exist') AND every output sentence is post-verified against the position/lines (Lucidfish EvidenceIndex: legal-move-for-side, piece-on-square-exists, capture-matches-history; chess-annotator consistency: eval-size words, side-better sign, capture/check claims, tactic terms must be in facts, forbid 'centipawn'). Failing sentences → one correction round → drop sentence. ACT-Eval shows even GPT-5.4 is 22% wrong on sub-claims without tools, so verification is not optional.
- BAR 3 — Human-length refutations: cap displayed punishing lines at the ply where the material/mate consequence is realized (walk the PV with a material/SEE counter and stop at the first decisive material swing or mate), rather than dumping 10–20 plies (chess.com users: 'five or six-move sequence at least'; lila dumps 20 plies).
- BAR 4 — Explain the opponent's mistakes too (what you could have punished = 'Miss'), 'Great'/'only move' moments, and the last book move, not just the player's errors. The repo has no Miss/Great/Book detection today (score.ts:75-119 only ??/?/?!/!!/!/!?); `Annotation` already reserves "⊗" Miss and "□" Only move (annotation.ts:187-189), so classification can be extended without schema change.
- BAR 5 — Game-level narrative that is cumulative, not per-move only (DecodeChess criticism 'per-move, not cumulative'): structure by phases via getGamePhases (phase.ts:77) → opening (name/ECO + where theory left), turning points (largest win-chance swings from node.score walk as in getGameStats), 'what decided the game', 2–3 takeaways each citing a move number (Lucidfish rule: takeaways must cite a move or verified fact).
- BAR 6 — Always-available and offline: chess.com gates explanations behind Diamond and they are intermittently missing even then; DecodeChess free tier is 1 game/day. Deterministic templates must produce acceptable commentary with no key configured (Chess-Move-Analyzer/stockfih pattern), and the LLM must be a strict upgrade in phrasing/selection over the same facts, never the sole source of content.
- BAR 7 — Localized: chess.com is English-only; En Croissant ships 16 locales, so deterministic commentary must be i18next keys with interpolation (and the LLM prompt must take `lang` as a request parameter like kibitz's `explanations: HashMap<lang,String>`).
- BAR 8 — Transparent and inspectable: show the facts the prose was generated from ('What the coach sees' panel in Chess-Move-Analyzer; stockfih keeps engine facts and model text visibly separate) and surface the arrows/squares for threats and the better move as `shapes` on the node ([%cal]/[%csl]), which chess.com and DecodeChess both do and which the repo already supports.
- BAR 9 — Deterministic, reproducible classification: emit verdict only at final depth (kibitz: 'a move can read Blunder at depth 6 and Good at depth 12'); fix the known trap that mate scores leak into cp swings (stockfih known issue; repo clamps mate to ±1000 via CP_CEILING, score.ts:15 — handle mate→cp and cp→mate transitions with explicit lila-style MateCreated/MateLost/MateDelayed wording).
- BAR 10 — Never over-award '!!': stockfih and chess.com both get criticized for generous Brilliant; the repo's `is_sacrifice` is a material-only qsearch heuristic (chess.rs ~505-515) — commentary should say 'sacrifice' only when the SEE/material loss is real and the eval holds, and should not call routine checks/captures brilliant.
- ARCH 1 — Three-layer pipeline mirroring kibitz/Lucidfish/chess-annotator, implemented in Rust (shakmaty already a dependency, Cargo.toml:24): (1) Facts layer: per-ply `MoveFacts` built from the existing `MoveAnalysis` (MultiPV=2 lines, score, depth) plus deterministic extractors — motifs on the refutation PV, hanging pieces with SEE, king-safety attackers/shield pawns, pawn-structure sets, open files, mobility, center attacker counts, material diff, StaticDiff before→after, phase, opening name; (2) Selection/ranking layer: pick which facts explain the verdict (max 2–3), deterministic; (3) Rendering layer: template renderer (i18n) OR LLM renderer with the same `MoveFacts` JSON + verifier. The LLM is a pluggable `CommentaryRenderer` trait/interface, not a different pipeline.
- ARCH 2 — Capture facts before `addAnalysis` discards them: today only `best[0].score` is persisted (tree.ts:693+). Either extend `MoveAnalysis` (chess.rs:449) with a `facts: MoveFacts` field computed in Rust during `analyze_game` (cheap, has shakmaty positions in hand, keeps TS bindings via specta), or persist `best` lines on the node. Prefer Rust-side facts so the deterministic layer is unit-testable with FEN fixtures and independent of React state.
- ARCH 3 — Storage: write the final commentary into the existing `TreeNode.comment` (Markdown) so it round-trips through PGN `{}` comments (chess.ts:117-118), the existing Comment.tsx renderer and AnnotationEditor, and stays user-editable; keep the structured `MoveFacts` separately (new optional field or side map keyed by path) so regeneration/translation/LLM upgrade can re-render without re-running the engine. Do not overwrite a user's hand-written comment without an explicit merge policy.
- ARCH 4 — Provider integration: add a Rust `tauri::command` using reqwest for the LLM call (streaming SSE), avoiding widening the webview `http:default` allowlist (capabilities/main.json:43-53) and keeping the key out of the webview; store the key via a settings atom (precedent: `sessionsAtom` tokens in localStorage, atoms.ts:213) but flag that plaintext localStorage is the current norm and an OS keychain (e.g., tauri-plugin-stronghold/keyring) is the upstream-quality option. Provider abstraction should allow Anthropic Messages API, OpenAI-compatible endpoints (covers Ollama/LM Studio for fully local LLM), with explicit opt-in before any game data leaves the machine (chess-game-review `allow_cloud_api` pattern).
- ARCH 5 — Prompt contract (adapt kibitz, GPL-compatible): system prompt with the five prohibitions (no pieces/squares/lines not in JSON; don't re-judge classification; no generalities; don't assert opponent intent — attribute lines to the engine; don't invent numbers), fixed output order (verdict → punishment/what the better move achieves → 1–2 positional reasons), word budget (~60–120 words per move; 120–200 for key moments), address as 'you', moves in SAN exactly as given, language parameter. Request JSON `{ply, comment}` with a strict schema; one repair attempt then fall back to the template text for that ply (chess-game-review pattern) so the UI never shows nothing.
- ARCH 6 — Verification module (deterministic, TS or Rust): tokenise SAN/pawn-move references and check legality for the attributed side in {position before, after, refutation line, best line}; check 'the/your X on sq' existence; check capture/check/mate words against actual move flags; check magnitude words vs |eval| bands; check tactic vocabulary against the motif list; strip or regenerate offending sentences; log violations for telemetry/tests. Reuse the regex rule catalogue from chess-annotator (MIT) and the sentence-level evidence index idea from Lucidfish (ideas only — unlicensed).
- ARCH 7 — Selection policy for which moves get prose: all ??/?/?!/!!/!/⊗ plus phase boundaries and the last book move by default; optional 'every move' and 'key moments only' detail levels (Lucidfish). Maia-style human-likeness (annotation-agent) is out of scope but the selection interface should allow extra triggers later.
- ARCH 8 — Game narrative generation: derive deterministic inputs (opening name, phase plies, per-phase accuracy, top-3 swing moves with their facts, result) and either template it or ask the LLM with those inputs only; verify result/colour attribution/verdict agreement (Lucidfish review checks). Place it at the top of ReportPanel above AccuracyCards, with each cited move clickable via `goToAnnotation`-style navigation to the node.
- ARCH 9 — UX placement options grounded in the repo: (a) inline — commentary as the node's Markdown comment under the move in GameNotation/Comment.tsx (matches ChessBase/PGN conventions, exportable); (b) report tab — narrative + 'key moments' list in ReportPanel; (c) engines tab — an on-demand 'Explain this position' using the live `engineMovesFamily` lines for the current node (AnalysisPanel.tsx:308) which is closest to DecodeChess's per-position Decode button. Mark LLM-generated text visibly (badge) and expose the fact panel.
- ARCH 10 — Evaluation/test strategy to show at interview and to upstream: golden FEN+PV fixtures for each motif extractor; snapshot tests of template output per locale; a verifier test-suite with seeded hallucinations (wrong piece, wrong side, nonexistent square, 'centipawn') proving they are caught; optional ACT-Eval-style atomic-claim precision measurement on a held-out set of real games. Avoid LLM-as-judge for faithfulness (ACT-Eval: near-perfect scores for unfaithful prose).
